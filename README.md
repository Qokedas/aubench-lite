# AUbench-lite

A reproducible agentic benchmark built on real Sorama CAM1K 1,024-microphone array
captures. The evaluated model plays a hired engineer: a rig owner hands it one raw
recording, an evaluator-generated reference heatmap tensor presented to the model as
a vendor export, and a delivery contract — nothing else. The model must reverse the raw device format,
recover the channel/geometry mapping from the metadata, derive the acoustics, and ship
a reusable program. The frozen program is graded on unseen raw captures (later
excerpts, a different scene, and synthetic controlled fields) inside a networkless,
read-only Docker runner.

## Minimum-slate design

The agent receives exactly three things (see `agent/BRIEF.md`):

1. `/data/capture/` — the first 2.5 s of the `axcar1` capture in the device's native
   format: channel-major little-endian `int32` `sound` plus Sorama `container.json`.
2. `/data/vendor_export/maps.npy` — the ground-truth tensor for that same
   recording (the single "anchor"). The brief presents it as a vendor software
   export; that is fictional client framing — see Provenance below.
3. The brief: invocation ABI, output tensor contract, camera view (pinhole,
   70.42° x 43.3°, 24 x 32), block length, and the 11 vendor band edges.

**Provenance.** Raw samples are bit-exact excerpts from the official SHA-pinned
Seeing With Sound captures (byte counts and digests pinned in `constants.py`);
benchmark packaging minimally updates the accompanying metadata (duration, and the
secret per-run channel ordering during grading). The dataset does
not include processed beamforming tensors, so the anchor and all hidden references
are generated by this repository's frozen conventional delay-and-sum reference
(`cam1k_eval/reference.py`). The brief's "vendor export" wording is part of the
client fiction in the evaluated prompt: the task is to build the instrument that
reproduces the specified conventional method, with the anchor as its exemplar.

Deliberately absent: any preprocessed arrays, the scan geometry, channel-ordering
semantics, the reference algorithm, the scoring metric, and any oracle service. The
channel permutation is recoverable from `container.json` plus physics (the correct
reading focuses; the wrong one does not), orientation and framing are pinned by the
anchor, and the beamforming math is the engineering task itself. Faithful
conventional implementations converge to the reference: window/DC/edge-convention
variants agree with the anchor to within 0.1% in raw dB-map correlation. The
published skill metric renormalizes by floor headroom, which amplifies small
residuals, so benign convention variants score 0.85–1.00 (calibration table below);
the anchor is the benchmark's declared conventional-DAS target, and faithful
implementations of that method converge to it.

## Anti-cheat grading (skill scoring)

Similarity metrics over dB-canonicalized maps have a high floor: static blobs overlap.
This benchmark therefore grades **skill above an uninformed floor**, per (frame, band)
map:

```
skill = max(0, (score - floor) / (1 - floor))
```

The floor is the best raw score achieved by a family of audio-independent baselines:
the public anchor and its blurs, gamma warps, flips, and shifts; a per-band physics
blob prior; and climatology templates the grader computes from the hidden references
themselves. This is a strong empirical floor family, not a formal optimum of the
composite metric: every fixed-output strategy we constructed, including ones outside
the family, scores at or below 0.06 overall. Each
map's skill is weighted by its floor headroom, so bands that physics makes
uninformative stop granting credit. Measured calibration:

| candidate | score |
|---|---|
| honest delay-and-sum | 1.00 |
| minor geometry-convention error | ~0.86 |
| right algorithm, wrong channel normalization | ~0.46 |
| center-bin-only shortcut | ~0.19 |
| replay/blur/amplify/warp/flip of public data, blob priors, noise | ≤ 0.02 |

Hidden real excerpts start at non-block-aligned offsets disjoint from the visible
interval. Every graded run secretly shuffles the raw stream's rows and composes
`channelOrdering` in the mounted metadata to match — invisible to honest programs,
fatal to hard-coded ones. Weights: 60% hidden real map skill, 20% hidden real hotspot
skill, 20% procedural cases (plane waves, dual sources, broadband, muted channels,
gain mismatch, incoherent noise, zero input — the zero case accepts a correct
all-zero map).

## Dataset

The public Drive of the Seeing With Sound dataset stores CAM1K data in `set3` as a
1,920,000,000-byte channel-major `int32` `sound` file and a Sorama `container.json`
per capture. `data download` verifies exact byte counts and SHA-256 digests. Note
that the dataset's ROS1 bags (`set1`/`set2`/`set4`) contain no CAM1K pressure topic
(lidar/IMU/cameras/GNSS only) — `cam1k-eval data inspect-bag <bag>` verifies this.

Docs: [overview](https://princeton-computational-imaging.github.io/seeingwithsound/),
[platform](https://princeton-computational-imaging.github.io/seeingwithsound/docs/platform.html),
[format](https://princeton-computational-imaging.github.io/seeingwithsound/docs/format.html).

## Reproduce

Requirements: Docker Engine/Desktop 29+, `uv`, ~8 GB free disk.

```bash
./scripts/bootstrap.sh
source .venv/bin/activate

cam1k-eval data download --root data/source
cam1k-eval data build --source data/source --output data/benchmark

docker compose build
pytest
./scripts/integration_test.sh   # DAS baseline >0.90, zero baseline <0.10
```

Grading is pure vectorized NumPy/SciPy over 24 x 32 maps and runs in seconds on any
laptop CPU; candidate execution inside Docker dominates wall time. Independent
replication needs no GPU and no network beyond the initial dataset download.

Reproducibility note: dataset manifests embed a build timestamp, so a rebuilt
benchmark is content-identical but not byte-for-byte manifest-identical, and no
dependency lockfile pins the exact host scoring environment. The published reports
record the manifest, submission, and output hashes actually used for the graded
runs.

## Submission ABI

A submission directory contains `solution.py` (plus optional regular files; ≤1,000
files, ≤100 MB). The runner invokes:

```bash
python /submission/solution.py --capture /input/capture --output /output/maps.npy
```

`/input/capture` holds a raw `sound` + `container.json`. Output must be finite,
nonnegative `float32 [frame, 11, 24, 32]` linear relative power, one frame per full
8,192-sample block.

## Security domains

1. The development container mounts only the public data and a writable episode
   workspace. It has **no network**.
2. The candidate runner mounts one secretly permuted raw capture, the immutable
   submission, and an empty output directory: no network, no capabilities, read-only
   root, non-root user, PID/CPU/memory/file limits, wall timeout.
3. The host grader never imports candidate code; it validates `maps.npy` and compares
   against references that were never mounted anywhere.

For a public adversarial service, run Docker itself inside a disposable VM. The local
setup provides strong process/container separation but does not claim Docker Desktop
is a hostile multi-tenant boundary.

## Model harness

`scripts/run_agent_eval.py` drives an evaluated model with a single `shell` tool into
the isolated development container. Both the OpenAI Responses API (`gpt-*`) and the
Anthropic Messages API (`claude-*`) are supported; the provider is inferred from the
model name. API keys load on the host from a dotenv file (default: `.env` in the
repository root, gitignored) and are never mounted into any container. Episodes are
fully isolated from each other and safe to run in parallel.

```bash
.venv/bin/python scripts/run_agent_eval.py --model claude-fable-5   --max-actions 80
.venv/bin/python scripts/run_agent_eval.py --model claude-opus-4-8  --max-actions 80
.venv/bin/python scripts/run_agent_eval.py --model gpt-5.6-sol      --max-actions 80
```

Each episode writes its transcript, workspace, frozen submission, and grade report
under `episodes/` and `reports/` (gitignored). The eight published runs (four models,
two rounds each) are exported with transcripts and frozen submissions under
`results/`; the aggregated numbers are in `results/AUBENCH_LITE_DATA.md`.

## Spoilers

`docs/REFERENCE_SOLUTION.md` is the answer key: a step-by-step derivation showing the
task is solvable from the agent-visible artifacts alone, with the discriminating
measurement for every decision. It is never mounted into any container (see the
containment audit in that file). If you hand this repository to a human solver as a
challenge, exclude `docs/`.
