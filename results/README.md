# AUbench-lite — published runs

Eight episodes: four models, two rounds each. Round 1 without the action budget stated,
round 2 with it stated. Each directory holds the grade report, the model-response log
(assistant messages and issued shell commands; the harness did not persist tool outputs
or user messages), and the frozen submission exactly as graded.

Provenance notes: the anchor the models compared against is generated by the frozen
evaluator reference; the brief presents it as a vendor export as part of the client
fiction (disclosed in the repository README). The harness was configured to build the
agent container from `docker/Dockerfile.agent`; the exact agent-image digest was not
recorded. Grading used the `cam1k-runner` image recorded in each report, with a fresh random grading permutation per run (seed
recorded in each report). Fable round 1 reached the 80-action cap, so its submission
directory was frozen as-is — a graded draft rather than an explicitly finalized
submission.

## Prompts used in these runs

All eight runs used the same system instruction, identical to the harness in this
repository:

"You are the evaluated coding agent, not a consultant. Continue making concrete
progress with shell calls until the submission is complete. Do not request user
input. Hidden data is unavailable and must not be guessed or exfiltrated."

User message (all runs): "Work autonomously in /workspace. Read /workspace/BRIEF.md
and complete the request in it. Use the shell tool for everything. Finish only after
qokedas-submit reports the submission is ready."

Round 2's user message additionally stated the 80-action budget explicitly. With one
stochastic run per model per condition, round-to-round differences should be read
descriptively, not as a controlled ablation; both rounds produced the same layout
failure in every run. The OpenAI transcripts echo the run-time system instruction in their
`instructions` field and can be checked against the above.
